# Tour Pass 远端调研报告分析与本地研究综合

- 分析日期：2026-09-28（UTC+8）
- 远端来源：`docs/research/Tour-Pass调研报告.md`，上游提交 `0d34bc5c`（2026-09-27）
- 本地代码基线：`56a60e42`；该基线早于上游调研报告提交
- 文档性质：对上游报告及本地既有研究的综合摘要；不是新的代码审计、渗透测试或市场调查

## 一页结论

远端报告和本地几份研究基本指向同一件事：Tour Pass 的差异不应押在“再生成一份更长的 AI 行程”，而应落到**行程核验、目的地执行知识和高质量旅行手册交付**。远端建议先聚焦井冈山红色研学/学生经济游；本地研究则补足手机阅读、离线/网页交付、打印 QA，以及从旅行需求到出版物的生产流程。

建议把它们合成一条产品主线：**用户可以从空白生成，也可以导入已有攻略；系统把行程变成有证据、能执行、可维护的旅行手册。** 保留轻量快速规划作为入口，不要求每个用户都走深度手册流程。

## 远端报告的主要结论

1. **工程判断**：报告将结构化输入、确定性组装、硬校验、证据/未知状态和可重放评测视为现有基础能力。以上是报告作者的代码阅读结论，本摘要未逐项重新审计实现。
2. **真实运行观察**：作者在 2026-09-27 做了一次访客场景的线上规划测试，指出目的地实体绑定、景区内交通、预约入口和约束提取会影响行程是否可执行。报告同时承认线上样本只有一次，建议用覆盖更多场景的测试集复核。
3. **定位建议**：面向井冈山及相似目的地，形成“行程体检 + 地方交通/预约知识 + 可分享旅行手册”的组合；先把一个垂直目的地做准，再评估复制。
4. **能力建议**：建立人工校准且注明来源/采集日期的地点别名与实体资料；结构化景区交通和预约规则；清晰区分已核验、未知和失败；允许导入已有行程；把手机阅读、打印和分享作为正式交付链路。
5. **竞品调研边界**：报告列举了国内、海外和开源方案，但竞品功能、排名、可用性等会变化。报告中的市场观察是 2026-09-27 的资料快照，不等于市场规模或持续竞争优势的证明。

## 与本地研究的交叉验证

本地工作区中已有数份未提交研究材料（基于 2026-09-24 左右的代码基线），方向与远端报告互补：

- **生产复盘**强调问题不只是提示词或样式：需求、事实来源、路线、内容、图片资产、出版配置和 QA 之间缺少可持续的生产对象与门禁。
- **导出交付研究**建议响应式网页作为主要阅读载体，PDF 作为经过独立排版和自动 QA 的打印/归档备份；离线和弱网体验仍需设备实测。
- **手机导览竞品研究**指出阅读叙事、现场执行和质量审计不应以同等视觉权重挤在一条长页面；应保留证据，但把会改变行动的信息放在首屏/路线层，把完整审计放在可展开的核验层。

综合来看，远端报告补上了“先从哪个场景切入、该补哪些地方数据”；本地研究补上了“如何把数据、内容和质量门禁组织成用户真正愿意使用的交付物”。两边并不冲突。

## 建议的落地顺序

### 0. 先做安全与隐私复核

远端报告包含线上服务安全风险章节。本摘要有意不复述可操作的漏洞细节、请求路径或利用步骤。报告中的安全结论应作为**待核查线索**，由维护者逐项确认适用版本、影响范围、修复状态和回归测试；来源级观察与线上验证应分开标注。完成复核前，不要把未经确认的细节扩散到用户材料或公开营销内容。

### 1. 井冈山数据最小闭环

优先整理核心地点/别名、景区内交通、预约与开放规则；每条信息保留来源、采集日期和失效/复核策略。数据过期或无法确认时回退为“未知”，不要静默显示成已核实。

### 2. 建立可重复的验证集

用多种人数、预算、日期、出行方式和天气场景构成回归集。分别统计地点实体绑定、交通覆盖、预约信息覆盖、冲突/不可执行项，以及“未知”是否被错误计为通过。单次演示和单一完整度分数不足以证明质量提升。

### 3. 打通“生成或导入 → 体检 → 手册”

先复用现有行程模型与校验能力，允许用户粘贴已有计划；再把问题按可执行性排序，并提供证据和修正建议。快速规划继续保留，深度手册作为可选模式。

### 4. 分层交付并守住隐私

手机端优先展示下一站、交通、预约和关键提醒；完整证据审计可展开查看。网页作为主要阅读载体，PDF 作为可打印备份并加入分页检查。分享默认应采取最小披露原则，发布前明确告知公开范围，并用自动化测试验证分享快照不包含非必要的用户上下文。

## 建议的验收指标

- 核心地点实体绑定率，以及无法绑定时的显式提示率；
- 行程段交通方式/时长有证据支持的覆盖率；
- 预约与开放规则的来源覆盖率、时效合格率；
- 未知项与核验通过项被正确区分的比例；
- 回归集中的硬冲突和不可执行问题数量；
- 用户找到“下一步怎么走/要做什么”的时间；
- PDF 空白页、溢出和断页问题；
- 分享内容的隐私最小化测试通过率。

具体目标值应先测基线，再设门槛；不要把远端报告的建议目标直接当作已达成或已验证的产品承诺。

## 证据等级与未决事项

- **报告直接陈述**：远端报告在 2026-09-27 进行了单次线上体验，并基于源码阅读和外部资料形成建议。
- **交叉印证**：本地生产复盘、导出交付和手机导览研究与“从生成转向可执行交付”的方向相互支持。
- **综合判断**：先做单一目的地数据闭环，再扩成导入体检和手册，是比继续堆 Agent 更可验证的路线；这属于产品推断，不是已验证的市场结果。
- **尚待验证**：安全报告中的每项结论是否仍适用于当前远端部署；井冈山地方数据的权威来源与更新责任；体检功能的持续使用意愿；网页/PDF/离线方案在真实设备上的表现；该垂直模式能否复制到其他目的地。
