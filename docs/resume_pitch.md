# Tour Pass 简历表达草稿

## 项目名称

C++ AI 城市自由行行程规划引擎

## 项目描述

基于 C++17 开发面向自由行场景的城市多日行程规划算法服务，将景点、餐厅、酒店和夜间活动点建模为带时间窗约束的 POI 图，结合 Dijkstra/A* 最短路、Beam Search Top-K 调度、兴趣评分、餐饮插入、候选方案生成和文本检索，为用户生成结构化旅行计划，并通过 OpenAI/DeepSeek 兼容接口或本地模板生成中文行程解释。

## 项目职责

- 设计 POI 与通勤边数据模型，将开放时间、游玩时长、兴趣标签、热度和消费水平纳入规划约束。
- 实现基于 Dijkstra 的 POI 最短通勤时间计算，并在行程评分中加入距离惩罚。
- 设计多目标评分函数，综合兴趣匹配、必去景点、热度、价格、时间窗和用户节奏生成候选安排。
- 实现基于 Beam Search 的日内 Top-K 路线搜索，在上午、午餐、下午、晚餐、晚上等时间槽保留多个局部状态，避免单路径贪心过早收敛。
- 设计轻松少走路、紧凑多覆盖、文化优先、美食优先和雨天室内等候选策略，通过不同评分权重对比不同约束下的行程结果。
- 输出候选方案对比指标和站点评分拆解，将热度、兴趣、必去、通勤、价格和时间窗惩罚拆成可解释分项。
- 对候选方案进行 Pareto 非支配排序，标记评分、通勤、开放时间风险和必去覆盖之间的多目标取舍。
- 实现轻量 BM25 POI 检索，结合名称、标签、区域和描述字段权重返回匹配词与排序解释。
- 实现 LLM/模板解释层，使用内置 HTTP client 调用 OpenAI 兼容接口，并支持无 API Key 环境下稳定演示。
- 使用 `cpp-httplib` 提供 `/trip/plan`、`/poi/search`、`/route/shortest`、`/trip/alternatives`、`/itinerary/explain` 和 `/health` HTTP JSON API。
- 构建本地 Web 演示台，展示偏好输入、候选行程、路线带、每日时间轴、方案 KPI、路径耗时、替换方案和自然语言解释，便于面试现场演示。
- 输出站点级决策依据、优化前后通勤时间对比、约束命中说明和未安排原因，增强规划结果的可解释性。
- 建立 GitHub Actions 质量门禁，自动执行样例数据校验、跨平台 CMake 构建、CTest 和 API 冒烟验证。
- 建立性能基准脚本，输出核心接口 avg/p50/p95 报告，用于说明规划接口响应时间和回归风险。

## 项目亮点

项目把图搜索、Beam Search 时间窗调度、多目标排序、Pareto 非支配排序、评分拆解、候选方案对比、CI 自动验证和大模型解释生成结合起来，解决自由行规划中“去哪玩、怎么排、去哪吃、时间是否够用、为什么这样排”的实际问题；核心规划模块可作为独立 C++ 算法服务接入旅游类后端系统。
