# Comparison Matrix

| Production stage | This Codex run | Current Tour Pass | Recommended Tour Pass |
|---|---|---|---|
| 需求发现 | Codex 首轮没有抓住“可执行的人文旅行手册”的目标，直接进入内容生产；用户看到错误结构后才被迫逐项纠正 | 基准输入虽能保存大量自由文本，但缺少成品类型、验收目标和专题深度字段；复杂要求被塞入 notes | 先复述旅行目标和成品形态，再生成 Trip Brief；信息架构、内容密度、专题深度和交付渠道要先确认 |
| 约束建模 | 人工记住三人分流、酒店、节奏、晚归、房型预算 | 类型化日期、抵返、同行人、房型、预算、每日窗口较完整 | 增加 traveller/leg 级约束、不同成员分流、多个住宿段和交付偏好 |
| 行程骨架 | 反复重写后形成天津与济南的日主线 | 首轮 8,192 output tokens 截断；紧凑重试成功，但后续又删 6 个执行/夜游节点 | 保留快速骨架；深度模式按 Brief、日程、内容分阶段生成，并用字段级 patch 更新指定日期或地点 |
| 地点核验 | 用高德查询地址、坐标和逐段路线 | 已有 AMap POI 与 route | 抽成 Route Graph；每条边同时保存公共交通、打车、步行与国庆缓冲策略 |
| 城际交通 | 讨论北京/广州不同返程方式并保留多方案 | 基准中天津→济南被错误修成 flight，返程被压成“北京/广州”；evaluator 未接 rail | Traveller Leg 分人记录；偏好绑定具体 leg；评估链接 rail；开售日、候补、替代与行李成为可执行任务 |
| 餐饮 | 后补特色菜、片区和店铺建议 | 有 meal stop 与候选，但价格为空 | 建 Dining Dossier：招牌菜、客单价区间、排队、营业时间、预约入口、路线耦合 |

| 《潜伏》专题 | 从地点清单升级为剧情、人物、空间和现实原型分层说明 | 兴趣字段只能影响模型选点和短理由 | 建 Theme Thread，显式连接剧集情节、人物、地点、证据强度与剧透级别 |
| 图片 | 人工选择 Commons 实景图并在页面运行时生成 | 无图片资产模型 | Asset Manifest 保存原图、来源、作者、许可、焦点、裁切、替代文本、加载状态 |
| 预约票务 | 单独整理开窗日历、价格、证件、入口和失败备选 | 基准产生 12 个任务，但 deadline、URL、evidence 全空，仍被完整度判为通过 | Fact Ledger + Booking Task；规则带有效期、来源、开售计算、价格、证件、行李和 fallback |
| 页面编辑 | 用户在浏览器按区块批注，Codex直接改 HTML | 多轮聊天会重生成完整计划 | 批注锚定实体和区块；生成结构化 patch、展示 diff、批准后合并 |
| HTML 交付 | 独立制作手机导览，加入导航、折叠、清单和图片 | 固定 `renderPlan` | Publication Model 决定模块、顺序、展开状态、移动端行为和样式 profile |
| PDF 交付 | Codex 独立页面经历强制展开、等待图片、调 print CSS 和 contact sheet 目检 | Tour Pass 基准 PDF 为 21 页；day 级强制分页与避免拆分页规则造成多页大片空白 | 打印专用组件允许长 day 跨页；导出后自动生成页图、空白率和裁切报告，再人工抽查 |
| 导航兼容 | 高德 URI 在电脑可用，部分手机 PDF 阅读器无反应 | 生成高德 marker 链接 | 每地点同时提供 HTTPS 链接、短地址、复制按钮和二维码；按渠道做点击测试 |
| QA | Codex 独立成品靠人工浏览页面、PDF 页图与链接统计 | 实测 Hard Validator pass、84 分，但实体绑定仅 22.86%、开放核验为 0、预约不可执行；出版空白未被发现 | QA Report 分开计算需求保真、事实、路线、预约、内容、资产和出版，不用单一分数掩盖阻塞项 |
| 发布与更新 | 两个版本独立保留，更新靠人工重新导出 | 保存计划版本和公开快照 | 发布包绑定 Brief、Facts、Assets、Renderer 与 QA 的不可变版本；易变事实可单独刷新 |

## Key Boundary

当前 Tour Pass 的“完成”定义是：行程满足硬约束并成功渲染。建议流程的“完成”定义是：目标渠道的成品通过事实、内容、资产和出版验收，并且高风险易变信息有复核时间。
